*[English](README.md) · Русский*

**MCP-сервер для удалённого администрирования Windows по WinRM/NTLM.** Диагностика, просмотр и управление любым хостом Windows в домене из Cursor, Claude Code, Codex или любого другого клиента MCP (Model Context Protocol). Подключение выполняется под учётной записью вызывающего, пароль запрашивается во время работы. Пароли хранятся только в памяти сервера с TTL по простою и никогда не пишутся в журнал.

- **40+ инструментов**: файловая система, службы, реестр, журналы событий, сертификаты, процессы, сеть, планировщик задач и другое
- **Проверка общего секрета**: каждый запрос обязан предъявить `MCP_AUTH_TOKEN` как bearer-токен, и только после этого серверу становятся интересны заголовки идентификации
- **Идентификация пользователя**: каждый запрос несёт заголовок `X-AD-User`; пароль либо передаётся необязательным заголовком `X-AD-Password` (без запроса), либо запрашивается один раз и кэшируется в памяти
- **Никаких секретов на диске**: учётные данные не попадают ни в файлы конфигурации, ни в переменные окружения, ни в журналы

## Примеры запросов

- «Почему на `HOST1` почти закончилось место на диске C:?»
- «Посмотри в журнале событий ошибки за последние сутки.»
- «Служба Print Spooler остановилась — выясни причину и перезапусти её.»
- «Какой процесс занимает порт 443?»
- «Покажи сертификаты, истекающие в ближайшие 30 дней.»
- «Прочитай `HKLM:\SOFTWARE\MyApp` и покажи текущие настройки.»
- «Сравни `web.config` на двух серверах приложений.»

## Быстрый старт

```bash
echo "MCP_AUTH_TOKEN=$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')" >> .env
docker compose -f docker-compose.yml -p win-mcp up -d --build --force-recreate
```

`MCP_AUTH_TOKEN` обязателен — без него сервер не запускается. Compose публикует порт только на `127.0.0.1`; открывать его шире следует лишь за прокси с терминацией TLS.

## Переменные окружения

Сервер настраивается только через окружение, файла конфигурации нет.

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `MCP_AUTH_TOKEN` | — | Общий секрет, который каждый запрос обязан предъявить заголовком `Authorization: Bearer <token>` либо `X-MCP-Token`. **Обязательна**: без неё сервер завершается при запуске |
| `MCP_BIND_HOST` | `127.0.0.1` | Адрес, который слушает uvicorn. В образе переопределён на `0.0.0.0`, потому что внутри контейнера доступность определяется тем, как опубликован порт |
| `MCPO_PORT` | `8005` | Порт, который слушает uvicorn |
| `AD_PASSWORD_IDLE_TTL_SECONDS` | `3600` | Сколько секунд закэшированный пароль AD живёт без обращений. `0` отключает истечение, и пароль хранится до остановки процесса |
| `SFTP_CRED_IDLE_TTL_SECONDS` | `3600` | То же время простоя для закэшированных учётных данных SFTP |
| `LOG_DIR` | `/app/logs` | Каталог для `win-mcp.log` и `win-mcp-audit.log`. Создаётся с правами `0700`, файлы — `0600` |
| `LOG_LEVEL` | `INFO` | Уровень журнала сервера. На журнал аудита не влияет: он пишется всегда |
| `LOG_MAX_BYTES` | `10485760` | Размер, при котором файл журнала ротируется |
| `LOG_BACKUP_COUNT` | `5` | Сколько ротированных файлов хранить по каждому журналу |
| `AUDIT_MAX_OUTPUT_CHARS` | `2000` | Сколько символов stdout и stderr одного вызова попадает в журнал аудита. Агент при этом получает вывод целиком |
| `AUDIT_LOG_BODY` | `1` | Значения `0`, `false`, `no` или `off` оставляют в журнале только метаданные вызова: ни текста команды, ни вывода |

## Настройка клиента

Каждый запрос обязан нести общий секрет — заголовком `Authorization: Bearer <token>` либо `X-MCP-Token: <token>`. Он проверяется до того, как сервер начинает доверять `X-AD-User`: этот заголовок лишь называет вызывающего и при этом служит ключом кэша паролей и сеансов, поэтому без токена любой, кто дотянется до порта, мог бы назваться чужим именем.

`X-AD-User` обязателен. `X-AD-Password` необязателен: если его не передать, сервер один раз запросит пароль через механизм elicitation протокола MCP и закэширует его в памяти.

И запрос пароля, и подтверждения изменяющих операций опираются на elicitation, а его убрали из протокола MCP в редакции `2026-07-28`. С клиентом, который согласует эту редакцию, изменяющие инструменты откажутся выполняться и сообщат об этом, а не выполнят операцию без подтверждения; чтобы инструменты чтения оставались рабочими, передавайте пароль заголовком `X-AD-Password`.

### Cursor (`mcp.json`)

```json
{
  "mcpServers": {
    "win-mcp": {
      "type": "http",
      "url": "http://localhost:8005/mcp",
      "headers": {
        "Authorization": "Bearer <MCP_AUTH_TOKEN>",
        "X-AD-User": "<ваша-учётная-запись>",
        "X-AD-Password": "<ваш-пароль>"
      }
    }
  }
}
```

### Claude Code

```bash
claude mcp add --transport http win-mcp http://localhost:8005/mcp \
  --header "Authorization: Bearer <MCP_AUTH_TOKEN>" \
  --header "X-AD-User: <ваша-учётная-запись>" \
  --header "X-AD-Password: <ваш-пароль>"
```

### Codex (`~/.codex/config.toml`)

```toml
[mcp_servers.win-mcp]
url = "http://localhost:8005/mcp"
http_headers = { "Authorization" = "Bearer <MCP_AUTH_TOKEN>", "X-AD-User" = "<ваша-учётная-запись>", "X-AD-Password" = "<ваш-пароль>" }
```

Любой другой клиент MCP настраивается так же: укажите ему адрес streamable HTTP и передайте заголовки.

## Журналирование

В `LOG_DIR` (по умолчанию `/app/logs`) лежат `win-mcp.log` и журнал аудита `win-mcp-audit.log`; каталог создаётся с правами `0700`, файлы — с `0600`, и права переустанавливаются при каждой ротации.

Журнал аудита записывает каждый вызов вместе с текстом команды PowerShell и фрагментом её вывода. Поскольку в вывод могут попасть содержимое файлов, данные реестра, списки учётных записей и сертификаты, записываются только первые `AUDIT_MAX_OUTPUT_CHARS` символов (по умолчанию 2000) — агент при этом по-прежнему получает ответ целиком. Значение `AUDIT_LOG_BODY=0` оставляет в журнале только метаданные вызова: ни текста команды, ни вывода.
